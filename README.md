# میزان — سامانه مدیریت سوپرمارکت

برنامه فارسی و راست‌چین مدیریت خرید، فروش، انبار، سود، بدهی‌ها، مرجوعی و آرشیو اسناد. رابط با Next.js ساخته شده و داده‌ها در Supabase Postgres با RLS نگهداری می‌شوند.

## امکانات

- داشبورد روزانه و ماهانه با فروش، سود ناخالص/خالص، هزینه، طلب، بدهی و ارزش موجودی
- کالا، بارکد، واحد، قیمت، موجودی اولیه، حد سفارش و تاریخ انقضا
- خرید اتمیک با میانگین موزون، بچ انبار، ضمیمه خصوصی PDF/تصویر و حساب تأمین‌کننده
- صندوق فروش با بارکدخوان، پرداخت نقدی/کارت/ترکیبی/بدهی، FEFO و چاپ رسید ۸۰ میلی‌متری/A4
- مرجوعی جزئی یا ابطال کامل با اصلاح موجودی، سود و ردپای حسابرسی
- اشخاص، هزینه‌ها، هشدار موجودی/انقضا، خروجی Excel/CSV/PDF و ورود گروهی کالا
- تقویم جلالی، تومان، منطقه زمانی تهران، رابط موبایل/دسکتاپ و PWA

## اجرای محلی

نیازمندی‌ها: Node.js 24+ و pnpm.

```bash
pnpm install
copy .env.example .env.local
pnpm dev
```

بدون متغیرهای Supabase، برنامه در حالت نمایشی و فقط‌خواندنی با داده نمونه اجرا می‌شود.

## راه‌اندازی Supabase

1. یک پروژه جدید در Supabase بسازید.
2. محتوای `supabase/migrations/202609230001_initial.sql` را در SQL Editor اجرا کنید. این migration جداول، RLS، bucket خصوصی و RPCهای اتمیک را ایجاد می‌کند.
3. در Authentication یک کاربر با ایمیل `mehdimarzooghian@gmail.com` و یک رمز قوی بسازید.
4. ثبت‌نام عمومی را در تنظیمات Authentication غیرفعال کنید.
5. URL پروژه و Publishable Key را در `.env.local` قرار دهید. هرگز Secret/Service Role Key را در مرورگر یا مخزن قرار ندهید.
6. اولین ورود، فروشگاه و عضویت مالک را با RPC امن `bootstrap_owner_store` ایجاد می‌کند.

```env
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_YOUR_KEY
OWNER_EMAIL=mehdimarzooghian@gmail.com
NEXT_PUBLIC_OWNER_EMAIL=mehdimarzooghian@gmail.com
```

## استقرار Vercel

1. مخزن خصوصی را در Vercel Import کنید.
2. چهار متغیر محیطی بالا را برای Production و Preview وارد کنید.
3. Deployment را اجرا کنید و URL نهایی را در Supabase Authentication > URL Configuration به‌عنوان Site URL اضافه کنید.
4. بعد از ورود مالک، یک خرید و فروش آزمایشی ثبت و سپس حذف داده آزمایشی را از طریق مرجوعی/ابطال انجام دهید تا ردپای حسابرسی حفظ شود.

## مدل امنیت و حسابداری

- همه جداول تجاری دارای `store_id` و RLS هستند؛ فقط عضو فعال همان فروشگاه داده را می‌بیند.
- نسخه فعلی فقط حساب مالک را فعال می‌کند. نقش‌های `cashier` و `inventory_clerk` برای مرحله بعد در مدل و RPCها تعریف شده‌اند.
- اسناد نهایی مستقیماً حذف یا ویرایش نمی‌شوند. اصلاح از مسیر مرجوعی یا ابطال انجام می‌شود.
- فروش موجودی را به روش FEFO از بچ‌ها کم می‌کند ولی بهای تمام‌شده را با میانگین موزون متحرک ثبت می‌کند.
- مبالغ `bigint` و بر حسب تومان، تعدادها `numeric` و زمان‌ها UTC هستند؛ نمایش با تقویم جلالی و Asia/Tehran انجام می‌شود.

## ساختار مهم

- `src/app` — صفحات، Server Actions و احراز هویت
- `src/lib` — مدل‌ها، محاسبات، Supabase و واکشی داده
- `supabase/migrations` — migration کامل و قابل نسخه‌بندی
- `supabase/tests` — بررسی اولیه RLS برای محیط آزمایشی

فایل `.env.local`، کلیدها، cacheها و خروجی build در Git ذخیره نمی‌شوند.
